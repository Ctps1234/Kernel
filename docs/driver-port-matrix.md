# Matriz de portabilidade de drivers — topaz / Android Common 6.12

## Bases comparadas

- **Alvo 6.12:** [`EdMory/android_kernel_common_sm8850`](https://github.com/EdMory/android_kernel_common_sm8850), branch `aosp-new/android16-6.12-lts`, commit `0efd3abd3c356d644ea49f6ed37e9830b78d34e3`. Além da consulta via GitHub API, uma sparse worktree temporária em `/tmp` foi usada para aplicar e verificar os patches locais 0001–0011 em sequência; cada `git apply --check` e o `git diff --check` final passaram. Não há uma árvore completa versionada neste repositório e nenhum build foi feito. “Ausente no alvo” descreve a base antes dos patches locais e se limita aos caminhos consultados.
- **Referência vendor topaz:** [`MiCode/Xiaomi_Kernel_OpenSource`](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/tree/topaz-t-oss), branch `topaz-t-oss`, commit `345999da0be9cd37afdf87b15449d30b585a7091`, Android 13/5.15. É fonte de referência para port, não uma base compatível com KMI 6.12.
- **Referência Qualcomm Platform 5.0 R47:** o manifest fixa `kernel/qcom` em `1c96d1325813d872d0206ffafe70c88823c86d6c` (ref `kernel.lnx.6.12.r67-rel`) e a árvore devicetree em `66167e56588bd7c0c9ec91e1e5c464512f6c4db6`. O Makefile do `soc-repo` declara 6.11.0, e o `kernel/common` R79 do manifest não pôde ser recuperado; detalhes em [`gki-source-validation.md`](gki-source-validation.md). Tratar como fonte de dados/implementação vendor, não como alvo GKI validado.
- O estado de runtime vem da captura `/proc/modules`/`modules.dep`; o estado de DT vem do FDT ativo. Um nodo habilitado não prova que o driver correspondente esteja carregado.

## Dependências e serviços

- **Já disponíveis na base common 6.12 consultada:** `mdt_loader` (`drivers/soc/qcom/mdt_loader.c`), `pmic_glink`, `cfg80211`, QRTR/QMI e infraestrutura Qualcomm genérica. Cada payload/compatible vendor ainda requer validação.
- **Existem na referência Xiaomi, mas não na base common 6.12 consultada:** `drivers/soc/qcom/qcom_va_minidump.c`, `drivers/soc/qcom/msm_performance.c`, `drivers/soc/qcom/dcvs/`, `drivers/soc/qcom/panel_event_notifier.c` e parte da integração de suporte vendor. São fontes potenciais para port; APIs, exports, Kconfig e dependências precisam ser atualizados. O R47 é referência de plataforma/SoC e ainda não foi inventariado quanto a toda a camada de periféricos específica do aparelho.
- **Continuam sem fonte correspondente na base common 6.12 e na referência Xiaomi revisadas:** KGSL, camera-kernel/techpack do aparelho, QCACLD/ICNSS2 e touchscreen FocalTech específico. Isso não conclui a busca por código nesses componentes dentro de toda a árvore R47 nem em fontes privadas.
- `msm-mmrm`, `qcom_ramdump`, `wlan_firmware_service`, `cnss_prealloc`, `cnss_nl` e serviços correlatos não ficam resolvidos apenas por existir QRTR/QMI ou `mdt_loader`; mapear símbolo por símbolo usando dependências e nós reais.

## Ordem recomendada de integração

1. **Fundação de SoC/DTS:** a série 0001–0017, DTS/DTBO e configuração GKI passaram build de kernel/DTBs e validação de schemas/exemplos na run 39090488896. O gate `dt-validate` registra 2686 erros/695 assinaturas sem regressão; a PHY UFS está limpa e o próximo passo é alinhar o host mantendo `ufs_mem` para MCQ.
2. **Boot e serviços:** validar primeiro console/armazenamento em hardware; depois integrar minidump/DCVS/performance/panel notifier conforme necessários e com exports GKI compatíveis.
3. **Display e touch:** adaptar a DPU/DSI/painel e o touchscreen identificado, sem alterar o contrato HAL às cegas.
4. **Bloqueadores de userspace:** decidir separadamente KGSL/GPU, câmera e Wi‑Fi; escolher source compatível ou planejar migração de kernel/userspace. Portar o Goodix fingerprint da referência vendor se a identificação do sensor confirmar.
5. **Hardware:** nenhuma imagem foi bootada ou flashada. Build/schema check verdes não demonstram votos de clock/regulador, sequenciamento UFS, display, touch ou compatibilidade com HAL.

Os módulos atuais são de 5.15 e não devem ser carregados no KMI 6.12. Os arquivos `.ko` identificam interfaces/dependências, mas não provam que seu código-fonte esteja disponível nem que uma alternativa upstream preserve as funções Android atuais.
